# Worlds

Each world is a directory under `arena_simulation_setup/worlds/<name>/`. The
directory name is the canonical identifier consumed by `WorldIdentifier`.

## Directory layout

```
worlds/<name>/
├── world.yaml          # WorldDescription: zones, walls, doors, entities
├── map/
│   ├── map.png         # binary occupancy map (regenerated by touch_world)
│   ├── map.yaml        # ROS map-server metadata (resolution, origin)
│   └── map.world.yaml  # optional: Gazebo world file
├── scenarios/
│   └── <scenario>/
│       ├── scenario.yaml     # Scenario: static/dynamic obstacles, robot goals
│       ├── scenario.json     # alternative; ScenarioView tries .yaml first
│       └── hunav_<N>_behavior_tree.xml  # per-agent BT (referenced from scenario.yaml)
└── assets/
    └── <domain>/
        └── <asset_type>/
            └── <name>/       # world-local asset; overrides network-fetched assets
```

## `world.yaml` schema

Top-level key is `zones` — a list of zone objects. Each zone:

```yaml
zones:
- name: central_hallway          # required; used as floor name
  description: Main Central Hallway
  material:                      # MaterialIdentifier for the floor
  - Concrete_Smooth              #   string form: [domain/]name
  - {}                           #   or [name, modifiers_dict] tuple form
  corners:                       # polygon corners of the zone floor
  - {x: 8.0, y: 0.0, z: 0.0}
  walls:                         # list of Wall entries
  - start: {x: 8.0, y: 0.0, z: 0.0}
    end:   {x: 9.25, y: 0.0, z: 0.0}
    material:                    # optional: inline material (when kind is absent)
      name: Plaster_Wall
      domain: Common
      _modifiers: null
  - start: {x: 0.0, y: 25.1, z: 0.0}
    end:   {x: 8.0, y: 25.1, z: 0.0}
    kind: patient_room_walls     # optional: WallIdentifier name; overrides material
  doors:
  - name: main_hallway_entrance
    start: {x: 9.25, y: 0.0, z: 0.0}
    end:   {x: 10.75, y: 0.0, z: 0.0}
    kind: sliding
    width: 0.1
    height: 2.0
    material:
    - Aluminum_Anodized
    - {}
  elevators: []
  entities:
    static: []                   # list of Obstacle
    dynamic: []                  # list of DynamicObstacle
```

A `Wall` entry with no `kind` field generates a plain wall segment using the
`material` field (or the `wall` default material). A `Wall` with `kind: <name>`
is resolved via `WallIdentifier(name)` at simulation time —
see [tree/Wall.py](../src/arena_simulation_setup/tree/Wall.py)
and [shared/walls.py](../src/arena_simulation_setup/shared/walls.py).

## `map/` directory

A preview `map.png` + `map.yaml` can be rendered with `touch_world` (see
[scripts/touch_world](../scripts/touch_world)) for inspection. These are not
required at runtime: the runtime renders its own map from `world.yaml` in-process,
so editing `world.yaml` is enough. Use `touch_world --all` to also regenerate the
canonical per-level `world.yaml`.

`map.world.yaml` is a Gazebo world file and is not produced by `touch_world` —
it is hand-authored or produced by the `generate_world` pipeline.

## `scenarios/<name>/` schema

Resolved by `World.scenario` property which returns a per-world
`ScenarioIdentifier` class
([tree/World/World.py:202](../src/arena_simulation_setup/tree/World/World.py#L202)).
`ScenarioView.load()` tries `scenario.yaml` first, then `scenario.json`.

Current (structured) format:

```yaml
static:
  - name: desk_1
    model: office_desk             # ObjectIdentifier
    pose: [x, y, yaw]
dynamic:
  - name: hunav_1
    model: female_adult_medical_01 # PedestrianIdentifier
    behavior_tree: ./hunav_1_behavior_tree.xml
    pose: [4.0, 2.0, 0.0]
    velocity: 2.5
    desired_velocity: 2.5
    waypoint:
    - [4.0, 2.0, 0.0]
robots:
  - start: [x, y, yaw]
    goal:  [x, y, yaw]
```

Legacy format (deprecated) uses `obstacles.static` and `obstacles.dynamic` keys instead.

Per-agent BT files `hunav_<N>_behavior_tree.xml` are per-instance BTCPP v4 XML
files referenced by the `behavior_tree` field. They are authored or
auto-generated alongside the scenario file; the behavior tree library shipped
with this package lives in
[configs/hunav/behavior_trees/](../configs/hunav/behavior_trees).

## `assets/` directory

World-local assets take precedence over network-fetched assets because
`DynamicPaths.WORLD / 'assets'` is registered before `NetResolver` for every
domain asset type (see
[tree/__init__.py:56](../src/arena_simulation_setup/tree/__init__.py#L56)).

Layout mirrors the network structure: `assets/<domain>/<asset_type>/<name>/`.
A world that ships a custom `Wall` preset places it at
`assets/Common/Wall/<name>/<name>.yaml`.

## How `WorldIdentifier` resolves a name

`WorldIdentifier` is backed by a `FallbackResolver` rooted at
`ASS_DIR / 'worlds'`
([tree/World/World.py:271](../src/arena_simulation_setup/tree/World/World.py#L271)).
`FallbackResolver` does not check existence before returning the path, so
`.resolve()` succeeds even for worlds that do not exist yet (useful for
programmatic world creation).

`WorldIdentifier('hospital_1').resolve()` returns a `World` view object
wrapping `<ASS_DIR>/worlds/hospital_1/`. Call `world.load()` to parse
`world.yaml` into a `WorldDescription`.
